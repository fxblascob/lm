11. Formularios Web en HTML5

Estructura de <form>, controles interactivos con <input>, tipos modernos (email, tel, date, color, number), validación nativa sin JS, <label>, <datalist>, <select> y <fieldset>.

Índice HTML Ejercicios

1. Arquitectura de un Formulario Web (<form>)

Un formulario HTML es una interfaz interactiva que permite al usuario introducir datos para enviarlos a un servidor web (programado en PHP, Node.js, Python o Java) para su almacenamiento, procesamiento o autenticación.

Al enviarse, el navegador empaqueta la información en pares nombre=valor (asociados al atributo name de cada control). Por tanto, cualquier control que carezca de atributo name será ignorado por el navegador al enviar los datos.

Estructura general de la etiqueta <form>:
<form action="procesar.php" method="post" enctype="multipart/form-data">
    <!-- Controles del formulario: etiquetas, campos, botones -->
</form>
Atributo Valores comunes Propósito y Buenas Prácticas
action URL del script o endpoint Dirección a la que se remitirán los datos (p. ej. registro.php o /api/login). Si se omite, se envía a la misma página actual.
method post | get post: Envía los datos ocultos en el cuerpo de la petición HTTP. Obligatorio para contraseñas, datos confidenciales o subida de archivos.
get: Adjunta los datos visibles en la propia URL (?q=termino&pagina=2). Ideal para búsquedas y filtros consultables.
enctype application/x-www-form-urlencoded
multipart/form-data		 Codificación de envío. Si el formulario incluye campos de subida de archivos (<input type="file">), es estrictamente obligatorio definir enctype="multipart/form-data".
autocomplete on | off Permite o prohíbe que el navegador sugiera valores guardados previamente en el historial del usuario.
novalidate Atributo booleano Desactiva la validación nativa de HTML5 del formulario (muy útil durante fases de prueba o desarrollo).
Nota sobre action="mailto:...": En apuntes antiguos se enseñaba a enviar formularios directamente por correo con mailto:. En la web actual esto es obsoleto y desaconsejado: falla en casi todos los navegadores modernos y teléfonos móviles si no hay un cliente de correo de escritorio local configurado. Los formularios siempre se procesan mediante un script de servidor o servicio API.

2. La etiqueta <label> y la Ergonomía Táctil

La etiqueta <label> asigna un texto descriptivo a un control del formulario. No es un simple texto informativo: es un pilar de accesibilidad (WCAG) y ergonomía táctil:

  • Accesibilidad: Permite que los lectores de pantalla anuncien exactamente qué información debe introducir el usuario al enfocarse en el campo.
  • Ergonomía móvil: Al hacer clic o tocar con el dedo sobre el texto del <label>, el navegador coloca automáticamente el cursor en el campo de texto o conmuta la casilla/radio, facilitando el uso en smartphones.
Vinculación explícita con el atributo for (Recomendada):
<!-- El valor de "for" DEBE coincidir con el "id" del control -->
<label for="usuario" class="form-label fw-semibold">
    Nombre de usuario:
</label>
<input type="text" id="usuario" name="usuario" class="form-control">

3. Controles fundamentales: La etiqueta <input>

La etiqueta <input> es un elemento vacío (sin etiqueta de cierre) cuya apariencia y comportamiento se transforman radicalmente mediante el atributo type:

Tipo (type) Descripción y Comportamiento Ejemplo de Código
text Entrada estándar de texto en una sola línea. <input type="text" name="nombre">
password Entrada ofuscada (los caracteres se ocultan con puntos o asteriscos). <input type="password" name="clave">
checkbox Casilla de selección múltiple (independientes entre sí). Se pueden marcar varias. <input type="checkbox" name="acepto" value="si">
radio Opción excluyente. Los radios con el mismo atributo name solo permiten elegir uno a la vez. <input type="radio" name="turno" value="m">
file Permite seleccionar y subir ficheros locales del usuario (requiere enctype="multipart/form-data"). <input type="file" name="cv" accept=".pdf">
hidden Control invisible para el usuario. Transmite identificadores o tokens de sesión al servidor. <input type="hidden" name="token" value="xyz">
submit / reset Botones nativos para enviar el formulario o restaurar sus valores iniciales. <input type="submit" value="Enviar">
Mejor práctica: El elemento <button> frente a <input type="submit">

En HTML moderno es preferible utilizar el elemento contenedor <button type="submit"> en lugar de <input type="submit">. Permite incluir contenido HTML enriquecido en su interior, como iconos vectoriales, negritas o imágenes: 

<!-- Botón moderno con icono de Bootstrap integrado -->
<button type="submit" class="btn btn-primary d-flex align-items-center gap-2">
    <i class="bi bi-send-fill"></i> Enviar Solicitud
</button>

4. La Revolución de Tipos Nativos en HTML5

Uno de los mayores avances de HTML5 fue la incorporación de tipos de entrada semánticos que aportan validación automática y activan el teclado adecuado en smartphones:

Tipo HTML5 Teclado / Interfaz en Móviles Validación y Características Clave
email Teclado optimizado con @ y . Valida automáticamente que el texto contenga una dirección de correo válida con formato usuario@dominio.ext.
tel Teclado numérico telefónico Optimiza la marcación en smartphones. No aplica validación estricta por defecto por la variedad de formatos internacionales.
url Teclado con / y .com Exige que el valor comience por un protocolo válido (como https:// o http://).
number Teclado numérico con flechas Restringe la entrada únicamente a números. Soporta los atributos min, max y step.
date Selector nativo de calendario Muestra el selector de fecha nativo del sistema operativo (YYYY-MM-DD), eliminando librerías JavaScript pesadas.
time Selector nativo de reloj Permite seleccionar horas y minutos según el huso horario local del usuario.
color Paleta cromática gráfica Abre el selector de color del sistema y devuelve su valor en formato hexadecimal (p. ej. #20c997).
range Barra deslizante (slider) Permite seleccionar un valor continuo o gradual entre un valor min y max.
search Botón nativo de borrado rápido Campo de búsqueda de texto con una cruz nativa para limpiar la consulta rápidamente.

5. Validación Nativa en Cliente sin JavaScript

HTML5 permite validar la integridad de los datos directamente en el navegador antes de enviar la petición al servidor mediante atributos estándar:

required Atributo booleano que impide el envío del formulario si el campo está vacío, mostrando una burbuja de advertencia nativa.
pattern="expresion_regular" Exige que el valor cumpla una expresión regular (RegEx) concreta (p. ej. DNI español: pattern="[0-9]{8}[A-Za-z]").
minlength / maxlength Limita el número mínimo y máximo de caracteres permitidos.
min, max, step Fijan los límites inferior, superior y el salto numérico para tipos number, range o date.
placeholder Muestra un texto de ejemplo en gris claro que desaparece automáticamente en cuanto el usuario comienza a escribir.
Ejemplo de campo con validación nativa completa:
<label for="dni" class="form-label">DNI (8 dígitos y letra):</label>
<input type="text" 
       id="dni" 
       name="dni" 
       required 
       pattern="[0-9]{8}[A-Za-z]" 
       placeholder="12345678Z" 
       title="Ocho dígitos seguidos de una letra mayúscula o minúscula" 
       class="form-control">

6. Controles avanzados: textarea, select y datalist

A. Área de texto multilínea: <textarea>

A diferencia de <input>, tiene etiqueta de apertura y cierre. El texto por defecto se ubica entre ambas etiquetas (no en un atributo value): 

<label for="observaciones" class="form-label">Observaciones:</label>
<textarea id="observaciones" name="observaciones" rows="4" class="form-control" placeholder="Escribe aquí tus comentarios..."></textarea>
B. Menús desplegables: <select> y <optgroup>

Permite elegir una opción entre varias predefinidas con <option>. Podemos agrupar opciones temáticas mediante <optgroup label="...">: 

<select name="curso" class="form-select">
    <optgroup label="Grado Superior">
        <option value="daw" selected>1º Desarrollo de Aplicaciones Web (DAW)</option>
        <option value="dam">1º Desarrollo de Aplicaciones Multiplataforma (DAM)</option>
        <option value="asir">1º Administración de Sistemas en Red (ASIR)</option>
    </optgroup>
</select>
C. Sugerencias de autocompletado en HTML5: <datalist>

Combina la libertad de una caja de texto libre con la comodidad de un menú desplegable. El atributo list del <input> se enlaza con el id del <datalist>: 

<!-- Campo de texto con lista de sugerencias dinámicas -->
<label for="navegador" class="form-label">Elige tu navegador habitual:</label>
<input type="text" id="navegador" name="navegador" list="lista-navegadores" class="form-control" placeholder="Escribe para buscar...">

<datalist id="lista-navegadores">
    <option value="Google Chrome">
    <option value="Mozilla Firefox">
    <option value="Microsoft Edge">
    <option value="Apple Safari">
    <option value="Opera">
</datalist>
