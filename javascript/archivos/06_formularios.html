06. Validación de Formularios

Tema 6: Acceso a controles, expresiones regulares, Constraint Validation API y feedback

En esta lección:
1. Propósito de la Validación 2. Acceso a Formularios 3. Comprobación de Valores 4. Expresiones Regulares (RegEx) 5. HTML5 y Constraint Validation 6. Feedback y Bootstrap 5 7. Actividades

1. Propósito y Límites de la Validación en Cliente

La validación de formularios en el navegador del usuario tiene como objetivo proporcionar una experiencia de usuario (UX) ágil e instantánea, informando de errores ortográficos, formatos incorrectos o campos vacíos antes de enviar la petición a la red.

Regla de oro de seguridad web: La validación en cliente (JavaScript) NUNCA sustituye a la validación en el servidor (backend). Cualquier usuario puede desactivar JavaScript, manipular el código en DevTools o enviar peticiones HTTP directas vía cURL/Postman. La seguridad real se implementa siempre en el servidor.

2. Acceso a Formularios y Controles

Podemos acceder a los formularios a través de document.querySelector() o mediante la colección clásica document.forms:

const miForm = document.querySelector("#registroForm");

// Acceso a controles individuales mediante su atributo 'name' o 'id'
const inputNombre = miForm.elements["nombre"];
const inputEmail = miForm.elements["email"];
const selectPais = miForm.elements["pais"];
const checkTerminos = miForm.elements["terminos"];

3. Consulta y Comprobación de Valores

Campos de Texto y Selects

Se consulta la propiedad .value (conviene aplicar .trim() para ignorar espacios en blanco vacíos):

if (inputNombre.value.trim() === "") {
    alert("El nombre es obligatorio");
}
Checkboxes y Radio Buttons

Se comprueba la propiedad booleana .checked:

if (!checkTerminos.checked) {
    alert("Debe aceptar las condiciones");
}

4. Expresiones Regulares (RegEx) para Validación de Patrones

Una expresión regular es un patrón de búsqueda textual extremadamente potente. En JavaScript se define entre barras /patrón/ y se valida con regex.test(cadena):

Tipo de Dato Patrón RegEx Recomendado Explicación
Teléfono español /^[6789]\d{8}$/ Empieza por 6, 7, 8 o 9 seguido de exactamente 8 dígitos numéricos.
Código Postal /^(?:0[1-9]|[1-4]\d|5[0-2])\d{3}$/ Exactamente 5 dígitos entre 01000 y 52999.
Correo Electrónico /^[^\s@]+@[^\s@]+\.[^\s@]+$/ Estructura básica usuario@dominio.extensión sin espacios.
DNI / NIE /^[0-9XYZ]\d{7}[A-Z]$/i 8 dígitos (o letra inicial NIE) y letra de control final. 
const regexTel = /^[6789]\d{8}$/;
if (!regexTel.test(inputTel.value)) {
    console.error("Teléfono no válido");
}

5. Validación HTML5 y Constraint Validation API

HTML5 incorpora validación declarativa nativa mediante atributos en las etiquetas: required, type="email", minlength, maxlength, min, max, y pattern="...".

A través de JavaScript, la Constraint Validation API permite interactuar con esta validación del navegador:

elemento.checkValidity()

Devuelve true si el campo satisface todas sus restricciones HTML5, o false si infringe alguna.

elemento.setCustomValidity("mensaje")

Establece un mensaje de error personalizado. Si se pasa una cadena no vacía, el campo se considera inválido.

6. Ergonomía de Validación y Clases de Bootstrap 5

Para desactivar las burbujas nativas del navegador y utilizar el diseño profesional de Bootstrap 5, añadimos el atributo novalidate al formulario y gestionamos las clases .is-valid y .is-invalid:

const form = document.querySelector("#formContacto");

form.addEventListener("submit", function(event) {
    if (!form.checkValidity()) {
        event.preventDefault(); // Impide el envío si hay errores
        event.stopPropagation();
    }
    form.classList.add("was-validated"); // Activa estilos de Bootstrap
}, false);
