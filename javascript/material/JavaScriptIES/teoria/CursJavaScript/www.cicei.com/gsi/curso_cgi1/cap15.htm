LOS FORMULARIOS

Los formularios o forms son la respuesta aportada por el lenguaje HTML para generar en la pantalla cuadros de diálogo con el lector.

Como en un formulario en papel, se podrán realizar zonas en las que se introducirá un texto, casillas de verificación, listas de selección, etc.

Estos formularios no serán nunca otra cosa que ficheros que se rellenan; siempre se necesitará un elemento apropiado para tratar la información que se introduzca. Este elemento será casi siempre un programa (que se llaman scripts) que se ejecutará en un estacio del servidor reservado a ese efecto: el CGI o Common Gategay Interface.Muy a menudo el programador deberá escribir un script que permita establecer el diálogo entre el browser que somete su formulario y otro programa accesible desde la máquina servidor, como por ejemplo una base de datos.

FUNCIONAMIENTO DE UN FORMULARIO

Un formulario describirá mediante marcas HTML las zonas en las que el usuario rellenará su formulario. Cada una de estas zonas se identificará con un nombre simbólico, y cuando el formulario se envía al programa de tratamiento, éste recibe el identificador de cada zona y el valor introducido.

El programa o script encargado del tratamiento del formulario se ejecuta en el CGI del servidor, y puede estar escrito en el lenguaje de programción que prefiera (C, Fortran, Perl, Tcl, todos los shells Unix, Visual C++,Visual Basic, Apple Script, y cualquier lenguaje que tenga una salida estándar).

El fin de la edición del formulario se desencadena cuando se pulsa un botón.En este momento, y sólo entonces, el programa recibe el conjunto de los datos del formulario, que no tiene por qué tener todos los campos rellenados.

No se puede, por ahora, realizar interfaces con un control de la edición en tiempo real a través de páginas HTML, como por ejemplo que el terminal realize un chequeo de coherencia de los datos en el mismo momento en que se introducen. La transacción se efectúa de una sola vez y, si se ha entrado un dato erróneo, corresponde al script de tratamiento enviar un mensaje de error al usuario y volver a mostrar la pantalla de edición. Si el script está bien diseñado puede incluso reenviar la pantalla rellenando previamente todos los campos que eran correctos.

Antes de empezar la descrición de las marcas hagamos el inventario de los elementos a nuestra disposición para crear estos formularios. Se definirán tres clases de elementos:

  • Una clase input que se aplica a diferentes tipos de entradas:
    • campos de edición:
      • Campo texto
      • Campo texto oculto
    • diversos tipos de botones
      • Botón de sumisión (submit)
      • Botón de borrado (reset)
      • Casillas de verificació (checkbox)
      • Botón radio
  • Una clase select que se aplica a las listas:
    • menús despegables
    • listas con barras de desplazamiento
      • Lista
      • Campo de texto largo


DESCRIPCIÓN DE LAS MARCAS DE FORMULARIO

Estas marcas permiten fabricar una interfaz de edición, y a este nivel no vamos atratar aún La Programación CGI para el tratamiento del formulario. Sin embargo, se seleccionará el nombre de las variables que identificarán los elementos del formulario, y se escogerá simplemente el nombre del script que debe tratar los datos de este formulario. Corresponderá seguidamente al programador codificar el script.

  • <FORM> .... </FORM>

    Esta marca inicia un formulario. Entre estas dos marcas se situarán todas las marcas que generan los diversos botones, casillas de verificación, entradas de texto, etc; pero también texto HTML estándar que permite vestir el documento.Esta marca se completa obligatoriamente con dos atributos:

    • El atributo METHOD:

      Se dirige más bien al programacor que codificará el script. Se encontrará una descripción completa en el capítulo La Programación CGI. Digamos simplemente por el momento que este atributo puede tomar dos valores GET y POST indicando el método de transferencia al script de los datos adquiridos.

    • El atributo ACTION:

      La función de este atributo es indicar la acción a emprender (el script a ejecutar) cuando se hace clic en el botón de sumisión. ACTION define el URL del script que permite tratar el formulario.


    La sintaxis general de apertura de un formulario es pues:

    < FORM METHOD=tipo de método ACTION=URL_del_script >
  • Todas las marcas que se definirán ahora tendrán atributos comunes que definieremos seguidamente:

    • El atributo NAME

      Permite definir el nombre que, en el momento de enviar los datos al script, permitirá a éste identificar el origen de esos datos. Por ello se escribe siempre de la forma:

      ... NAME=nombre_de_la_variable_asociada

      ¡ATENCIÓN! El nombre que se va a atribuir aquí debe ser único en el formulario, salvo en el caso de un conjunto compuesto por varios elementos (checkbox o botón radio)

    • El atributo VALUE
      • Para un campo de texto, permite predefinir el contenido del mismo.
      • Para un botón de tipo submit o reset, indica el texto a escribir en el botón.
      • Para un botón de tipo checkbox, indica el valor asociado al botón cuando éste está pulsado (o marcado). El valor especificado por NAME identifica el bloque de botones.
      • Para un botón de tipo radio, indica el valor asociado al botón si éste está pulsado. El valor especificado por NAME identifica el bloque de botones.

  • <INPUT>

    Es la marca general que permitirá definir todos los elementos de la clase input.

    Sin atributo, la marca INPUT definirá una zona de entrada de texto simple; así la instrucción siguiente:

    <INPUT NAME="identidad">

    El atributo TYPE Puede tomar los siguientes valores:

    • SUBMIT: es el botón que desencadena el envío de todos los datos del formulario hacia su script de tratamiento; el texto definido por el atributo VALUE se escribitá en el botón:
      < INPUT TYPE="submit" VALUE="Aceptar">

      Esta instrucción provoca la visualización siguiente

      El INPUT de tipo submit no precisa atributo NAME porque el programa no utiliza datos para este botón que sólo tiene una función de disparador.

    • CHECKBOX: permite definir uno o varios valores que se atribuirán a una misma variable (definida por NAME).

      Por ejemplo, vamos a pedir al usuario que indique el o los microordenadores que utiliza. Las marcar HTML siguientes:

      < INPUT TYPE="checkbox" NAME="micro" VALUE="mac"> Macintosh <BR>
      < INPUT TYPE="checkbox" NAME="micro" VALUE="pc"> PC <BR>
      < INPUT TYPE="checkbox" NAME="micro" VALUE="ux"> Estación UNIX <BR>

      provocarán la visualización:

      Macintosh
      PC
      Estación UNIX

      La variable micro está está asociada a ñ los tres botones checkbox podrán tener el valor mac+pc si el individuo utiliza estos dos tipos de ordenadores.

    • RADIO: permitirá escoger una y sólo una opción entre n.
      Siguiendo nuestro ejemplo, vamos a pedir al usuario que indique si quiere una distribución en CD-ROM o en disquete:
      < INPUT TYPE="radio" NAME="medio" VALUE="cd" CHECKED> CD-ROM
      < INPUT TYPE="radio" NAME="medio" VALUE="dsk" > DISQUETE

      Provocará la visualización:

      CD-Rom
      Disquete

      El atributo CHECKED tiene como efecto posicionar un botón (CD-ROM) en modo marcado.

      Hacer clic sobre una opción deselecciona automáticamente las otras.

    • PASSWORD: es una zona de texto en la que los caracteres escritos se reemplazan sistemáticamente por asteriscos.

      Por ejemplo:

      < INPUT TYPE="password" NAME="pwd" >

    • RESET: este botón permite borrar en todo momento los datos que se está editando en el formulario; el texto definido por el atributo VALUE se escribirá en el botón:
      < INPUT TYPE="reset" VALUE="Borrar">

  • <SELECT> .... </SELECT>

    Es la marca reservada a las listas. Éstas pueden clasificarse en dos categorías:

    • Los menús desplegables (o pop-lists): se presentan en forma de un campo de texto y un botón para desplegar el menú.

      La marca <SELECT> abre una lista en la que cada ítem se define por la marca <OPTION>; el atributo SELECTED permite escoger la opción que se visualizará de forma predeterminada. Esta opción será la que se transmitirá al programa de aplicación si el usuario no selecciona otra opción.

      El código HTML siguiente:

      <SELECT NAME="paises">
      <OPTION SELECTED> España
      <OPTION> Portugal
      <OPTION> Francia
      <OPTION> Italia
      </SELECT>

      da la visualización siguiente:

    • Las listas con barra de desplazamiento (o scrolled lists): son listas que aparecen en una ventana con barra de desplazamiento y en la que se puede regular el número de items visibles. Se programán de forma idéntica a los menús desplegables pero con un atributo suplementario SIZE que indica el número de líneas visibles en la ventana. Por defecto, sólo se puede seleccionar una opción de la lista a la vez, salvo si se pone el atributo MULTIPLE que permitirá una selección múltiple.

      La programación de una lista con selección única es de la forma:

      <SELECT NAME="menu" SIZE=6> <OPTION>España
      <OPTION>Francia
      <OPTION>Portugal
      <OPTION>Italia
      <OPTION>Gran Bretaña
      <OPTION>Irlanda
      <OPTION>Holanda
      <OPTION>Bélgica
      <OPTION>Alemania
      <OPTION>Suiza

      <SELECT NAME="menu" SIZE=6 MULTIPLE>

  • <TEXTAREA> .... </TEXTAREA>

    esta marca permite crear una zona de texto especificando su tamaño mediante los valores que se asociarám a los atributos ROWS y COLS.
    ROWS indicará el número de líneas de la ventana mientras que COLS definirá el número de columnas.

    En esta ventana es posible predefinir un texto (entre las marcas <TEXTAREA> y </TEXTAREA>) que el usuario podrá reemplazar o completar por su propio texto.

    Por ejemplo:

    <TEXTAREA NAME="comentario" ROWS=10 COLS=40>
    Introduzca aquí sus comentarios
    </TEXTAREA>
