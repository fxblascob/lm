FORMULARIOS

Qué son los formularios?

Los formularios son una herramienta de HTML para permitir que los usuarios introduzcan información al servidor.

Cuando un usuario rellena los campos de un formulario y presiona un botón indicativo, el formulario envía los datos al servidor para su procesamiento. Normalmente, el servidor preparará un documento en HTML utilizando la información suministrada por el usuario y la devolverá a éste para su visualización; no obstante, las aplicaciones de los formularios son muy variadas: ordenar un producto, enviar comentarios, hacer una operación bancaria, inscribirse en una base de datos, etc...

Todo formulario consta de dos partes : una página HTML, el form propiamente dicho, y un script CGI encargado de procesar la información que esta página recoge.

Cómo se define un formulario

Un formulario se define dentro de un documento HTML, a través de las directivas <form>......</form>
Bases del uso de los formularios.

Todo formulario debe tener un atributo ACTION, que apunta hacia el ejecutable cgi-bin que lo procesa. Este ejecutable lo Único que recibe son pares del tipo nombre=valor, donde el nombre es el NAME identificador del campo de ingreso, y VALUE el valor de lo ingresado por el usuario.

Partes de un formulario.
  1. La directiva <form ACTION=".....">
  2. El cuerpo del formulario, consistente en texto y en una serie de campos de ingreso.
  3. Los botones para enviar el formulario y para limpiarlo.
  4. La directiva </form>
Todos los elementos deben estar dentro del form, o de lo contrario son ignorados.
El cuerpo del formulario.
EL cuerpo del formulario puede estar compuesto por elemento de tres tipos distintos:
  1. Una clase <input> que se aplica a diferentes tipos de entradas: campos de edición y diversos tipos de botones.

    Su sintaxis es la siguiente:

    <input name="..." type="..." [...]>

    El atributo type puede tomar uno de los siguientes valores:
    • text
    • password
    • checkbox
    • radio
    • hidden
    • submit
    • reset
  2. Una clase <select> que se aplica a las listasmenús desplegables, listas con barra de desplazamiento.
  3. Una clase <textarea> que se aplica a una zona de edicion de texto libre.

Todo estos campos de ingreso tienen asociado un NOMBRE, que es obligatorio asignar, pues si no se hace así no habrá ninguna manera de referirse a la información que el usuario ha ingresado.

Qué es CGI

CGI (Common Gateway Interface) es una interfase entre aplicaciones externas y servidores de información, que define la forma de codificación de los datos y el lugar en el que deben estar disponibles: variable de entorno o entrada estándar.

Un documento HTML es algo estático, permanente, que no se adecúa a las necesidades de interactividad, acceso a información en constante actualización, consulta a base de datos o seguimiento, control o recuperación de resultados de un determinado proceso. Por ello, a veces es necesario acceder a una información que se está generando en timepo real. Así pues, es preciso contar con algún tipo de pasarela como la que define CGI.

Esta interfaz define una forma cómoda y simple de ejecutar programas que se encuentran en la máquina en la que se aloja el servidor. Para el cliente presenta una ventaja en el aspecto de la seguridad, ya que no tendrá que ejecutar ningún programa de efectos desconocidos en su sistema local. El acceso se realiza a través de cualquier cliente estándar de WWW y la comunicación se realizará según el protocolo HTTP.

Sin embargo, aunque en el servidor ya no será necesario permitir el acceso a extraños, un webmaster deberá saber que tener un programa CGI equivale a "QUE TODO EL MUNDO podrá ejecutar un programa en MI sistema", por lo que sí será necesario tener en cuenta algunos aspectos fundamentales de seguridad. El más básico suele ser la necesidad de incluirlos programas CGI en un directorio determinado reservado al efecto, al que generalmente se le llama cgi-bin, directorio que no suele ser accesible a todos los usuarios. Cuando un servidor WWW recibe como petición un documento alojado en este directorio, entenderá que se trata de un programa ejecutable.

Un ejecutable básicamente toma la entrada de un formulario, y devuelve una página HTML. También puede consultar o hacer cambios en el disco del servidor donde fue activado. Por último también puede abrir una conección a otro computador, etc.

Para crear un ejecutable cgi-bin se puede usar cualquier lenguaje que pueda generar ejecutables.

Invocando un CGI

La forma más simple de invocar a un CGI es mediante un URL que apunte al fichero ejecutable, que se encontrará en el directorio reservado al efecto. El servidor, al recibir una petición dentro de este directorio comprenderá que se trata de un programa y lo ejecutará. Esto ocurrirá cada vez que se acceda al URL correspondiente. Por ejemplo, supóngase que el servidor se encuentra en mi_maquina.mi_demonio.es, el directorio de CGI's es cgi_bin y el programa CGI recibe el nombre de no_se_que_hago. Bastará abrir desde un browser de WWW el URL:
http://mi_maquina.mi_demonio.es/cgi-bin/no_se_que_hago

Al ejecutarse un CGI, su salida estándar queda inmediatamente conectada con el servidor de información, que le hará llegar al cliente. Un programa CGI puede devolver cualquier tipo de información, desde un simple texto ASCII , a una imagen GIF, a JPEG o ...pasando por una animación, código HTML y un largo etcétera.

Un browser será incapaz de mostrar esta información de forma correcta si no conoce de qué naturalez es, del mismo modo que se producirán efectos inesperados si se trata de abrir un fichero GIF con un editor de texto. Por ello, la interfaz especifica una serie de cabeceras que los scripts pueden utilizar para proporcionar este tipo de información. Así, aunque la salida del script es un flujo de datos, se puede considerar divididi en cabeza y cuerpo. Entre las cabeceras, la más importante es la que especifica el contenido: Content-type: tras ella, debe indicarse el tipo MIME a que pertenece la información que será generada por el documento. El tipo se indica de la forma tipo/subtipo. Porejemplo: Content-type:image/jpeg

Resulta extremadamente importante, dejar una línea en blanco entre las cabeceras CGI y el contenido de la información. Si no se hace así, el sistema no funcionará y el cliente no podrá acceder a la información.

Qué son las variables de entorno.

Las variables de entorno son unas variables que se les asigna un valor determinado cuando el servidor ejecuta el programa CGI invocado desde el formulario; esto es cuando lanza el script cgi, el demonio httpd posiciona toda una serie de variables de entorno. Estas variables juegan un papel capital en la programación cgi: permitirán al desarrollador el acceso a numerosas informaciones, respecto al servidor, el cliente, la máquina que ejecuta el cliente, etc.. Se trata de uno de los medios de comunicación entre el servidor y el script cgi. La entrada estandar se utiliza también para este fin en ciertas condiciones (método POST).

Veamos la lista de variables de entorno (originales) creados por el demonio antes de ejecutar un script cgi. Las tres primeras variables no dependen de la consulta efectuada por el cliente:
SERVER_SOFTWARE

Nombre y versión del demonio httpd que ejecuta el script cgi.
Formato: nombre/versión

SERVER_NAME

Nombre de la máquina que ejecuta el demonio httpd o dirección IP si esta máquina no tiene número IP.

GATEWAY_INTERFACE

Nivel de versión de la pasarela cgi del servidor Web.
Formato: cgi/versión

Las variables siguientes son específicas de una petición dada:

REMOTE_USER

Esta variable sólo se utiliza en aquellos servidores que soportan autentificación de usuarios y el script llamado por la consulta está protegido; esta variable indica el nombre del usuario de origen de la petición.

CONTENT_LENGTH

Se carga con la longitud total de los datos enviados por el cliente en un formulario. Esta variable permite en particular conocer el número de carácteres a leer de la entrada estándar en el tratamiento de un formulario con el método POST.

SERVER_PROTOCOL

Nombre y versión del protocolo utilizado por la cunsulta en curso del tratamiento.
Formato: Protocolo/versión

SERVER_PORT

Número del puerto (en el sentido IP) hacia el que ha sido enviada la petición.

REQUEST_METHOD

Método con el que se ha efectuado la petición. Esta variable es particularmente útil en el tratamiento de formularios. Permite saber si un formulario se gestiona con el método GET o con el método POST.

SCRIPT_NAME

Nombre del script a partir de la raíz del servidor Web. Por ejemplo:
SCRIPT_NAME= /cgi-bin/test_script

REMOTE_HOST

Nombre de la máquina de origen de la petición. Si esta máquina no tiene nombre, el servidor informa solamente con la variable REMOTE_ADDR.

REMOTE_ADDR

Dirección IP de la máquina de origen de la petición.

AUTH_TYPE

Si el servidor permite la autentificación de usuario y el script llamado por la consulta está protegido, esta variable indica el método utilizado para validar el usuario.

REMOTE_IDENT

Esta variable no se soporta en todos los servidores. Cuando está posicionada, indica el nombre del usuario conectado (en el sentido del sistema operativo)en la máquina de origen de la petición.

CONTENT_TYPE

Para las peticiones que conducen datos, esta variable indica el tipo de datos enviados por el cliente.
Formato: MIME. En el caso del tratamiento de un formulario con el método POST por ejemplo, sería:
application/x-www-form-urlencoded

PATH_INFO

Es la cadena de caracteres que empieza tras el nombre del script y termina antes del carácter "?" o al fin del URL si no existe el "?". Contrariamente a la cadena QUERY_STRING, esta cadena va simpre escrita literalmente en los URL, y no es generada nunca por el cliente.

QUERY_STRING

Es la cadena de caracteres que sigue al primer "?" tras el nombre del script y se termina al final de URL.
Tiene dos orígenes posibles:

  • o bien se añade manualmente en un enlace de hipertexto, como en el ejemplo siguiente en el que se hace referencia al script /cgi-bin/anuario pasándole el valor "nombre=contreras" . Corresponde al script /cgi-bin/anuario el tratamiento de la cadena QUERY_STRING y utilizar la información que contiene

    <HTML>
    <HEAD>
    <TITLEW>Anuario</TITLEW>
    </HEAD>

    <A HREF="http://www.in2p3.fr/cgi-bin/anuario

  • obien es añadida por el cliente el momento en que éste envía su petición hacia el servidor Web. Cuando una página HTML es un formulario que utiliza el método GET o un documento ISINDEX y posee pues campos de edición, el cliente utiliza la cadena QUERY_STRING para enviar al servidor la lista de estos campos con sus valores.

PATH_TRANSLATED

Se trata de la variable PATH_INFO precedida de la raiz del servidor Web.
La construcción de esta variable puede ser diferente entre sistemas. Es por ello poco aconsejable utilizarla.

Además de las variables citadas hasta aquí, el servidor crea ciertas variables a partir de la cabecera HTTP de la petición enviada por el cliente. El número de estas variables dependerá pues del cliente que haya enviado la petición. Estas vartiables van precedidas por HTTP_.Veamos dos variables que se crean casi sistemáticamente:

HTTP_ACCEPT

Lista de tipos MIME aceptados por el cliente que ha hecho la petición.
Formato:tipo/subtipo, tipo/subtipo...

HTTP_USER_AGENT

Información respecto al cliente que ha hecho la petición.
Formato:aplicación/versión librería/versión

Lenguajes de programación CGI.

CGI define una serie de reglas que deben cumplir tanto las aplicaciones como los sevidores para hacer posible la presentación de resultados de programas ejecutables en tiempo real a través de servicios de información estandarizados. Por ello, se habla de gateway o pasarela entre una y otra dimensión. Al tratarse de una interfaz, no existe ninguna dependencia con el lenguaje de programación empleado y, del mismo modo, no presentará mayor dificulatd realizar un programa CGI en un lenguaje u otro, salvo la intrínseca al propio lenguaje.

En principio, cualquier lenguaje capaz de tener una salida estándar es susceptible de ser utilizado para desarrollar programas CGI, (o scripts CGI, en el argot) ya sea interpretado o compilado. En la red existen aplicaciones CGI desarrolladas en C (utils.c , libcgi ), C++, Fortran, Perl , Tcl , Visual Basic, AppleScript y cualquier shell de UNIX.

El lenguaje más utilizado en el mundo Unix es sin duda Perl. Es un lenguaje interpretado resultado de una mezcla de C, sed, awk y sh, y que se presta muy bien al desarrollo de scripts cgi. El C está también muy extendido en la programación del CGI. La compilación ofrece un mayor nivel de seguridad; permite asegurarse de que el código fuente de un script cgi no será nunca accesible a la red ni si quiera por error, cosa que no ocurre con un lenguaje interpretado.

Cómo es el formato en que se codifica la información procedente de un form.

La programación CGI aplicada a los formularios se diferencia de la programación CGI clásica en que el cliente debe enviar al servidor el conjunto de datos entrados por el usuario.

Se hace mediante pares nombre=valor separados por el signo "ampersand" (&); es decir:

nombre1=valor1&nombre2=valor2&.........&nombren=valorn

Los campos que pueden contener varios valores (como las listas de selección múltiples) aparecen con tantos pares nombre=valor como valores seleccionados.

nombre1=valor1&nombre1=valor2&nombre2=valor3&....

En definitiva, se utilice el método que se utilize, habrá que procesar la información recibida según los siguientes pasos:
  1. Extraer "tokens" considerando como delimitador el signo "ampersand" (&).
  2. En cada "token", realizar una nueva separación considerando como delimitador el carácter "igual" (=). La información que recibe el form, ya sea a través de la entrada estándar o de la variable QUERY_STRING se encuentra URL-codificada (URL-encoded), lo que significa que los espacios en blanco habrán sido substituidos por el signo "mas" (+), y los caracteres especiales se indican en hexadecimal precedidos por un signo "tanto por ciento" (%xx). El script CGI deberá, por tanto, recuperar los valores originales.

Cómo se envía información al servidor desde un formulario

El envío de información se sustenta sobre el protocolo HTTP y se puede realizar a través de dos métodos definidos en el mismo: GET Y POST. Por tanto, resulta necesario indicar uno de estos dos valores en el atributo METHOD de la etiqueta <FORM> es decir <FORM METHOD = metodo ACTION=script> donde script es el URL correspondientes al programa CGI encargado de procesar la información del form.
Diferencias entre GET y POST.

Si el método elegido es GET, el servidor creará una variable de entorno para el CGI denominada QUERY_STRING e introducirá en ella toda la información del form siguiendo el formato de codificación que se expuso anteriormente.

Si, por el contrario, el método elegido es POST, el servidor proporcionará toda la información al CGI a través de la entrada estándar del mismo, siguiendo el mismo formato que si se hubiese utilizado el método GET.
Conveniencia del uso de GET y POST.

Se desaconseja el uso del método GET para el envío de información de un form a un CGI debido a que se realizará a través de una variable de entorno que puede tener una longitud más o menos limitada segÚn el sistema. Por ello, la información presente en el form podría desbordarla.

Seguridad

Es importante mencionar que a la hora de programar CGI es necesario considerar que se trabaja en un entorno concurrente en el que hay que tener especial cuidado en el acceso a datos compartidos. Hay que considerar que mientras se está accediendo a ciertos datos otros programas puede estar cambiándolos. Por ello, habrá que utilizar alguna técnica de programación concurrente.

La descripción de los métodos que utilizaremos se aplica en un demonio HTTPD de tipo NCSA instalado en una máquina UNIX, con versión 1.0 a 1.5 o posterior.

Autentificación del usuario.

Salvo indicación contraria, las páginas de un servidor Web son accesibles desde toda Internet. Sin embargo, el acceso a una página o a un conjunto de páginas en un servidor se puede restringir. Estas restricciones pueden gestionarse según diferentes criterios.

  • El acceso puede reservarse a usuarios en posesión de una palabra clave. El concepto username/password es totalmente independiente de las cuentas UNIX.

  • El acceso también puede darse a usuarios pertenecientes al mismo ámbito o subámbito (puede tomarse en el sentido TCP/IP).

  • Se puede utilizar una combinación de ambos métodos

  • Sería posible realizar un método particular desarrololando un script adaptado.

Principio de la Autentificación.

Si queremos realizar una restricción de páginas web en un directorio denominado protegido y hacer que puedan acceder al mismo ciertos usuarios de la máquina en donde trabajamos, debemos crear un fichero .htaccess en dicho directorio. El sistema de autentificación se desencadena cuando el servidor detecta en el directorio que contiene el documento a transmitir la presencia de dicho fichero;la lectura del mismo le indicará cuál es el tipo de protección en uso en este directorio.

Este tipo de autentificación es muy flexible ya que permite gestionar diferentes directorios con criterios de acceso distintos.

Autentificación por palabra clave.

Inicialmente creamos una base de datos cuyo nombre es .htpasswd que contendrá las personas autorizadas a acceder al documento.

En un servidor de tipo NCSA se proporciona una utilid ad para crear y gestionar esta base de datos. Se trata del programa htpasswd.

Una vez situados en el directorio donde deseamos que se encuentre la base de datos, se crean simultáneamente (opción -c) la base de datos .htpasswd y el primer usuario.

% htpasswd -c bdgpwd/.htpasswd david1
Adding password for nombre_usuario.
New password:
Re-type new password:
%

Seguidamente se pueden crear otros usuarios
Para visualizar el contenido de la base:

% cat bdgpwd/.htpasswd

A continuación nos posicionamos en el directorio que contiene los ficheros HTMLa proteger. En este directorio se crea el fichero .htaccess que deberá contener las siguientes líneas:

AuthUserFile /users/ddis/httpd/support/fichero2
AuthGroupFile /dev/null
AuthName ByPassword
AuthType Basic

<Limit POST GET>
require user jenrique falayon fortes jomis secrdis
</Limit>

El fichero fichero2 sería tal como este con los nombres de los usuarios y sus claves encriptadas:

jenrique:717Ye/PM1vcp
falayon:WMPkq8JB8SPYs
fortes :d5Ej/CIwGQfCU
jomis:..tDN6zLxG30c
secrdis:W8ufeCKQY5Etk

También es posible gestionar grupos de usuarios. Para ello basta con crear un fichero .htgroup (siempre en un directorio de su elección). Este fichero se estructurará con se indica en el siguiente ejemplo:
admin-grp: secrdis
systm-grp: fortes jomis
visit-grp: jenrique falayon

Cada directorio podrá abrirse a los grupos afectados según se indique en el fichero .htaccess, como por ejemplo:

AuthUserFile /users/ddis/httpd/support/fichero2
AuthGroupFile /users/ddis/httpd/support/fichero3
AuthName ByPassword
AuthType Basic

<Limit POST GET>
require group admin-grp
require group systm-grp
</Limit>

(ver httpd://hoohoo.ncsa.uiuc.edu/docs-1.5/tutorials/user.html)

Autentificación por la red.

En este método se autorizará el acceso a un grupo de usuarios pertenecientes a un mismo ámbito. Por ejemplo se ofrecerá el acceso a las páginas HTML exclusivamente a los usuarios provenientes del ámbito .fr y del ámbito .cern.ch o se prohibirá el acceso atodos los usuarios del ámbito .pepita.fr.

Al principio sigue siendo el mismo, sólo el contenido del fichero .htaccess es diferente.

Se ofrecen dos posibilidades:

  • Se rechazan todos los accesos salvo aquellos que se necesitan

    AuthUserFile /dev/null
    AuthGroupFile /dev/null
    AuthName AccessRestreint
    AuthType Basic

    <Limit GET>
    order deny, allow
    deny form all
    allow form .fr
    form .cern.fr
    </Limit>

  • Se aceptan todos los accesos salvo los que se indican

    AuthUserFile /dev/null
    AuthGroupFile /dev/null
    AuthName InterditPartiel
    AuthType Basic

    <Limit GET>
    order allow, deny
    allow form all
    deny form pepita.fr
    </Limit>

Glosario de Términos.

ASCII:
American Standar Code for Information Exchange (Código normalizado americano para el intercambio de información). Se trata de un código que le asigna a cada letra, número o signo empleado por los ordenadores con su combinación de ceros y unos correspondientes. &EACUTE;ste es el código más ampliamente usado por todos los ordenadores a nivel internacional. El código ASCII le asigna ocho bits a cada carácter.
Base de Datos:
Cualquier conjunto de información alamacenada en cualquier formato. Generalmente, el término se aplica a texto o a información gráfica almacenada en un ordenador y accesible de forma sistemática. La información de una base de datos suele estar dividida en registros, y éstos, en campos.
Cliente:
Es un software que trabaja en el ordenador local para poder hacer uso de algún servicio del ordenador remoto. El software del ordenador remoto que permite ese uso recibe el nombre de servidor.
Correo electrónico:
Es una aplicación que permite enviar mensajes a otros usuarios de la red sobre la que esté instalado. En Internet, el correo electrónico permite que todos los usuarios conectados a ella puedan intercambiarse mensajes.
Demonio:
En los sistemas UNIX, se le da estre nombre al software servidor. Este software está siempre en funcionamiento en segundo plano, esperando a que una aplicación cliente solicite sus servicios.
Ftp:
Es una aplicación de Internet que permite transferir ficheros de un ordenador a otro. Las siglas se corresponden con File Transfer Protocol, protocolo de transferencia de ficheros. Las siglas FTP tambien pueden hacer referencia al propio protocolo.
HTML:
Hypert Text Markup Language. Se trata de un formato especial de ficheros sobre el que está basada la estructura de la aplicación WWW (World Wide Wed).
Http:
Protocolo para Sevidores Web.
Internet:
Es un conjunto de redes de ámbito mundial conectadas entre sí mediante el protocolo IP( Internet Protocol). A través de Internet se puede acceder a servicios como transferncia de ficheros, acceso remoto, correo electrónico y noticias entre otros.
IP:
Siglas significan Internet Protocol (protocolo internet). IP es el protocolo de nivel de red (interred) usado en Internet. Mediante el protocolo IP, cualquier paquete puede viajar a través de las distintas redes de Internet hasta llegar a su destino final. IP es la clave del funcionamiento de Internet.
Listas de correo:
Es un servicio de Internet mediante el cual los mensajes de correo que llegan a una determinada dirección son reenviados a todos los componentes de una lista. Cualquier usuario puede voluntariamente subscribirse o borrarse de cualquiera de las listas existentes. Generalmente, cada lista trata de un tema distinto, y los usuarios que tienen algo que decir sobre un tema particular envían sus mensajes a la lista correspondiente. Existen miles de listas distribuidas por internet que cubren la mayoría de los tamas imaginables.
Netscape:
Cliente de Web.
Pasarela:
Es un sistema informático que transfiere datos entre dos aplicaciones o redes incompatibles entre sí. La pasarela (gateway) adapta el formato de los datos de una aplicación a otra o de una red a otra. La pasarela se utiliza generalmente para interconectar dos redes distintas o para hacer que una aplicación entienda los datos generados por otra aplicación distinta.
Protocolo:
Es un conjunto de normas que indican cómo deben actuar los ordenadores para comunicarse unos con otros. Los protocolos definen desde para qué se va a usar cada hilo de un conector, hasta el formato de los mensajes de un correo electrónico.
Puerto:
Por un lado, puede ser un número que identifica una aplicación particular de Internet. Cuando un ordenador envía un paquete a otro, el paquete contiene la información de qué aplicación está intentando comunicarse con el ordenador remoto. Esta identificación se hace mediante un número de puerto.
Por otro lado, también se conoce como puerto al conector físico que utilizan los ordenadores para comunicarse con el exterior (puerto de impresora, puerto serie, etc...). Los dos significados son completamente distintos, y no tienen nada que ver uno con el otro.
Servidor:
Se trata de un software instalado en un ordenador, llamado remoto, que le permite a este ofrecer un servicio a otro ordenador , llamado local. El ordenador local contacta con el ordenador remoto gracias a otro software llamado Cliente . También puede recibir el nombre de servidor el propio ordenador donde está instalado el software servidor.
Telnet:
Es una aplicación de Internet usada para acceder a otros ordenadores de la red. Mediante esta aplicación se puede hacer uso de una gran variedad de servicios, como acceso a bases de datos.
Unix:
Es un sistema operativo multitarea y multiprogramación. Este sistema operativo, aunque fue muy importante en el desarrollo de Internet, no es necesario saber usarlo para usar Internet.
VI:
Editor de texto de Unix.
WWW:
Significa alg asi como entresijo mundial. Se trata de un potente sistema utilizado para localizar y acceder a las fuentes de información de Internet. El World Wid Web es un protocolo que permite a los usuarios hacer que su información sea fácilmente accesible para los otros usuarios. El WWW es un sistema Cliente /Servidor que soporta referencias de Hypertextos.
X windows:
Se trata de un estándar pensado para los ordenadores que trabajan con UNIX y que permite que los dise¤adores de software puedan escribir aplicaciones gráficas utilizables en una gran variedad de terminales. Existen aplicaciones X-windows para una gran variedad de sistemas cliente-servidor, entre ellos Gopher, Usenet news, Correo electrónico o WWW.
