06. Herencia, Cascada y Especificidad en CSS

La letra «C» de CSS significa Cascading (en cascada). Comprender cómo se heredan las propiedades entre elementos padres e hijos y cómo calcula el navegador el peso exacto de cada regla (especificidad) es el conocimiento técnico más determinante para escribir código limpio y predecible.

1. El Principio de Herencia (Inheritance)

Cuando un elemento padre tiene asignada una propiedad CSS, algunos de sus estilos se transmiten automáticamente a sus descendientes. Sin embargo, no todas las propiedades se comportan igual:

Propiedades Heredables (Por defecto)

Afectan principalmente al texto y la tipografía:

  • color Color del texto
  • font-family, font-size, font-weight Tipografía
  • line-height, letter-spacing Espaciado texto
  • text-align, visibility Alineación
Propiedades No Heredables

Afectan a la caja física, fondo y disposición espacial:

  • margin, padding Márgenes y rellenos
  • border, border-radius Bordes
  • background (color e imágenes) Fondos
  • width, height, display, position Dimensiones / Layout
Control Explícito de Herencia: Valores Universales
inherit Fuerza al elemento a tomar el mismo valor que tenga su contenedor padre directo (incluso en propiedades no heredables como border: inherit;).
initial Restablece la propiedad al valor por defecto fijado en la especificación oficial de la W3C.
unset Si la propiedad es heredable actúa como inherit; en caso contrario, actúa como initial.

2. Cálculo Riguroso de la Especificidad

Cuando dos o más reglas compiten por dar estilo al mismo elemento, el navegador calcula una puntuación de especificidad dividida en cuatro categorías (A, B, C, D):

Categoría Tipo de Selector Peso Ejemplo
A: En línea Atributo style="..." 1, 0, 0, 0 <p style="color: red;">
B: Identificadores Selector de ID (#id) 0, 1, 0, 0 #menu-principal
C: Clases y Atributos Clases (.btn), Atributos ([type]), Pseudoclases (:hover) 0, 0, 1, 0 .nav-link:hover → (2 clases/estados: 0, 0, 2, 0)
D: Elementos Etiquetas HTML (p, div) y Pseudoelementos (::before) 0, 0, 0, 1 article p::first-line → (0, 0, 0, 3)
Sin valor Universal (*), Combinadores (>, +, ~), :where() 0, 0, 0, 0 div > * → Aporta solo el peso de div (0, 0, 0, 1)
Ejemplo Práctico de Resolución de Conflictos
/* Regla 1: 1 etiqueta */
p { color: blue; }                        /* Peso: (0, 0, 0, 1) */

/* Regla 2: 1 etiqueta + 1 clase */
p.grupo { color: green; }                  /* Peso: (0, 0, 1, 1) - ¡Gana a Regla 1! */

/* Regla 3: 1 etiqueta + 1 ID */
p#tercero { color: red; }                  /* Peso: (0, 1, 0, 1) - ¡Gana a Regla 2! */

/* Regla 4: Estilo en línea en HTML */
<p id="tercero" style="color: gray;">      /* Peso: (1, 0, 0, 0) - ¡Gana a todos! */

3. Arquitectura Limpia: !important y @layer

¡Regla de oro profesional — Evita !important!: Agregar !important al final de una declaración anula por la fuerza el cálculo natural de la especificidad. Aunque parece una solución rápida para sobrescribir estilos rebeldes, rompe el principio de cascada y hace que el mantenimiento a largo plazo sea una pesadilla. En su lugar, aumenta la especificidad del selector o reordena los archivos CSS.
La Solución Moderna en CSS3+: Capas de Cascada (@layer)

Las capas de cascada permiten estructurar las reglas en niveles lógicos de prioridad independiente (por ejemplo: reseteo, componentes y utilidades). Las reglas de una capa superior siempre vencen a una inferior, sin importar la especificidad interna de sus selectores: 

/* Definición del orden de prioridad de capas (de menor a mayor) */
@layer base, componentes, utilidades;

@layer componentes {
    .tarjeta {
        background-color: #ffffff;
        padding: 1.5rem;
    }
}

@layer utilidades {
    .bg-dark {
        background-color: #212529; /* Prevalece sin necesidad de !important */
    }
}
